The +919194… bug

In otp_login_page.dart the field uses FilteringTextInputFormatter.digitsOnly and _buildIdentifier() returns '$_selectedCountryCode$trimmedValue'. When the keyboard autofills or the user pastes +91 94744 14563, the + and spaces are stripped, leaving 919474414563, and the page prepends +91 again → +91919474414563. _isPhone only checks ^[0-9]+$, so nothing catches it. The verify page then hard-codes '+91 ' in the mask regardless of the chosen country.

Fix: normalise before building the identifier — strip non-digits, drop a leading 0, drop a leading country code that matches the selected one (91 + 10 digits → 10 digits), then validate 10 digits for +91. Show the cleaned number back in the field so the seller sees what will be sent.

Today · password first

/loginPassword page→ link"Login with OTP"→ /login-otpPhone / email→ /otp-verification6-digit code

Problems: every logout / token-expiry lands on the password page most users never set; OTP is two taps away; phone-vs-email toggle + country picker + prefix logic is split across two pages that each format the number differently.

Proposed · OTP first, password as fallback

/loginPhone → Get OTP→ /otp-verificationVerify · /login-passwordPassword (bottom link)

Wins: one tap to a code on the number they already own; one shared phone-number widget and normaliser used by OTP, password and signup; password still one tap away; every existing context.go('/login') call keeps working.

Implementation plan

Small, in the existing bloc pattern. OtpBloc and LoginBloc do not change.

1 · Fix the number (ship first)

  • Add lib/common/phone_number_util.dart with PhoneNumberUtil.normalise(raw, dialCode) + unit tests (paste with +91, with spaces, leading 0, already-national, non-Indian code).
  • otp_login_page.dart: _buildIdentifier() and _validateInput() go through it; show cleaned number in the field.
  • otp_verification_page.dart: mask from the identifier's own dial code.
  • login_page.dart _getFormattedUsername() uses the same util.

2 · Route swap

  • app_routes.dart: /login → OtpLoginPage, add /login-password → Login(); keep /login-otp as a redirect to /login for old deep links.
  • auth_guard.dart: add /login-password to the public list.
  • Nothing else changes — auth_service.logout(), splash, dialogs all already go('/login').

3 · Shared phone widget

  • lib/common/widgets/phone_or_email_field.dart: country chip + number, or email; exposes identifier (e164 / email) and isEmail. Replaces the duplicated prefix/country-picker code in OTP, password and signup pages.

4 · Screens as drawn

  • OTP page: copy, "Use email instead" link, bottom divider + "Login with password" secondary button.
  • Password page: mirrored bottom button "Login with OTP instead"; drop the old text link.
  • Verify page: "Change" link, inline error, auto-submit at 6 digits, password fallback at bottom.

Open questions

  • Does the OTP API return attempts-left / lockout? (screen 03 copy)
  • Keep email-OTP at all, or phone-only for OTP and email only on the password page?
  • Add SMS auto-read (sms_autofill) now or later?
